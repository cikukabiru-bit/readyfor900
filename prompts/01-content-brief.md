# Wingu900 content brief (shared by all content writers)

Wingu900 ("wingu" = cloud in Kiswahili) is a free, UNOFFICIAL AZ-900 (Microsoft Azure Fundamentals) study web app built for a Power Learn Project Africa hackathon. Audience: African beginners, often first-time cloud learners. Judges weight **Learning Value (is the content accurate and genuinely helpful?)** most heavily.

## Hard rules
- Write ORIGINAL content. Never copy or closely paraphrase real exam questions, braindumps, practice-test sites, or Microsoft Learn sentences.
- Accuracy over cleverness. Use current product names (Microsoft Entra ID, not Azure AD). If you are unsure of a number or detail, leave it out rather than guess.
- Plain language, short sentences, friendly tutor tone. No marketing language.
- African examples: everyday life from across the continent (Kenya, Nigeria, Ghana, South Africa, Rwanda, Tanzania, Uganda, Egypt, Ethiopia...). Ideas: M-Pesa / mobile money, matatu / danfo / trotro, boda boda, prepaid electricity tokens, chama savings groups, eCitizen single login, mama mboga, estate gate and guard, landlord/caretaker/tenant, lorries carrying goods, renting vs building a house, a hotel vs cooking at home, harvest season, school fees season, salary-day rush. Do NOT claim facts about specific companies' technology (e.g. never say "M-Pesa runs on Azure").
- The only live Azure regions in Africa are **South Africa North (Johannesburg)** and **South Africa West (Cape Town)**, which are a region pair. Do not claim any other Azure region exists in Africa.
- Never use "All of the above", "None of the above", "Both A and B", or anything that refers to option letters/positions — options are shuffled at runtime.

## Accuracy notes (use these facts; don't contradict them)
- Shared responsibility: the customer is ALWAYS responsible for their information/data, devices (phones, PCs) and accounts/identities. The provider is ALWAYS responsible for the physical datacenter, physical network and physical hosts. OS, network controls, applications and identity infrastructure vary by IaaS/PaaS/SaaS. In IaaS the customer patches the OS; in PaaS the provider manages the OS.
- Cloud models: public (shared provider hardware), private (one organisation, can be on-prem), hybrid (both, connected). Multi-cloud = more than one provider. Azure Arc helps manage hybrid/multi-cloud.
- Consumption-based = pay for what you use, operational expenditure (OpEx) rather than capital expenditure (CapEx). Pricing models: pay-as-you-go, reservations (1- or 3-year commitment for discount), savings plans, spot (cheap spare capacity that can be evicted).
- Serverless: you don't manage servers; event-driven; you pay per execution/use (Azure Functions, Logic Apps). Servers still exist — the provider manages them.
- Scalability: vertical (scale up/down: bigger/smaller machine) vs horizontal (scale out/in: more/fewer instances). Elasticity = automatic scaling with demand. High availability is expressed through SLAs (uptime percentage). Reliability = ability to recover from failures and keep working. Predictability = performance predictability and cost predictability.
- Regions: a geographical area containing one or more datacenters. Most regions are paired with another region in the same geography (often 300+ miles apart); some newer regions have no pair — don't claim every region is paired. Planned Azure updates roll out to one region of a pair at a time. Sovereign regions: Azure Government (US) and Azure in China operated by 21Vianet.
- Availability zones: physically separate locations within a region, each with independent power, cooling and networking; a minimum of three separate zones in enabled regions; not every region supports them. Zonal vs zone-redundant services.
- A resource can belong to only ONE resource group; resource groups cannot be nested; deleting a resource group deletes everything in it; resources can be moved between resource groups. A subscription is a billing and access boundary. Management groups organise subscriptions; up to six levels of depth (not counting the root); each subscription/management group has one parent. Hierarchy: management groups > subscriptions > resource groups > resources. Settings (RBAC, policy) are inherited downward.
- Availability sets: fault domains (up to 3: separate power/network rack) and update domains (up to 20, default 5: rebooted one at a time). VM Scale Sets: identical, load-balanced VMs that autoscale. Azure Virtual Desktop: desktop and app virtualisation in the cloud. A VM needs: size, disks (storage), a virtual network, a network interface, optionally a public IP and a network security group.
- App hosting: Azure App Service (web apps, API apps; PaaS); containers via Azure Container Instances (simplest, single containers), Azure Container Apps, Azure Kubernetes Service (orchestration); VMs for full control.
- Networking: VNet = private network in Azure; subnets segment it; VNet peering connects VNets (also across regions — global peering) over Microsoft's backbone; Azure DNS hosts DNS zones (you cannot buy domain names through Azure DNS); VPN Gateway sends ENCRYPTED traffic over the PUBLIC internet (site-to-site, point-to-site, VNet-to-VNet); ExpressRoute is a PRIVATE connection through a connectivity provider that does NOT go over the public internet (not encrypted by default). Public endpoint = reachable via a public IP; private endpoint = a private IP address from your VNet for a service (Azure Private Link).
- Storage services: Blob (unstructured objects: images, video, backups), Azure Files (managed file shares, SMB/NFS), Queue (messages between app parts), Table (NoSQL key/attribute data), Disk (block storage for VMs). Storage account types: Standard general-purpose v2 (most scenarios), Premium block blobs, Premium file shares, Premium page blobs.
- Access tiers (blobs): Hot (frequent access), Cool (infrequent, stored at least 30 days), Cold (rarely accessed, at least 90 days), Archive (rarely accessed, at least 180 days, offline — must be rehydrated, which can take hours). Lower tiers = cheaper storage, higher access cost.
- Redundancy: LRS = 3 copies in one datacenter; ZRS = 3 copies across 3 availability zones in the primary region; GRS = LRS in primary + asynchronous copy to the paired secondary region; GZRS = ZRS in primary + copy to secondary region; RA-GRS / RA-GZRS = read access to the secondary region.
- AzCopy = command-line copy tool; Azure Storage Explorer = free graphical (GUI) app; Azure File Sync = keep a Windows file server in sync with Azure Files (with cloud tiering). Azure Migrate = hub to discover, assess and migrate on-prem servers/apps/data; Azure Data Box = physical device shipped to you for moving large amounts of data offline (e.g. slow/expensive network).
- Microsoft Entra ID = cloud identity and access service (sign-in, SSO, MFA, app access). Microsoft Entra Domain Services = managed domain services (domain join, Group Policy, LDAP, Kerberos/NTLM) without running domain controllers yourself. SSO = one identity for many apps. MFA = two or more of: something you know, something you have, something you are. Passwordless = e.g. Windows Hello for Business, Microsoft Authenticator app, FIDO2 security keys. External identities = let partners/customers sign in with their own identities (B2B collaboration; Microsoft Entra External ID).
- Conditional Access = uses signals (who, where, device, app, risk) to make decisions (allow, require MFA, block).
- Azure RBAC = roles assigned to a security principal at a scope (management group, subscription, resource group, resource); inherited by child scopes; built-in roles include Owner, Contributor, Reader, User Access Administrator; principle of least privilege.
- Zero Trust principles: verify explicitly; use least privilege access; assume breach.
- Defense in depth layers (outer to inner): physical security, identity & access, perimeter, network, compute, application, data.
- Microsoft Defender for Cloud = security posture management and threat protection across Azure, on-prem and other clouds (secure score, recommendations).
- Cost factors: resource type, consumption, maintenance (cleaning up unused resources), geography (region), network traffic (data leaving Azure/egress and between regions is billed; most inbound data transfer is free), subscription type, Azure Marketplace purchases. Pricing calculator = estimate cost of planned resources before deploying. Cost Management = see/analyse actual spend, create budgets, set alerts (budget alerts, credit alerts, department spending quota alerts), recommendations. Tags = name/value pairs on resources for organising, cost reporting and automation; tags are NOT automatically inherited from a resource group (Azure Policy can enforce/inherit them).
- Microsoft Purview = family of data governance, risk and compliance solutions (see and govern data across on-prem, multi-cloud and SaaS). Azure Policy = create/assign rules that enforce standards and evaluate compliance (e.g. only allow certain regions or VM sizes); policies can be grouped into initiatives; can deny non-compliant deployments and remediate. Resource locks = prevent accidental changes: CanNotDelete (Delete) allows changes but blocks deletion; ReadOnly blocks changes and deletion. Locks apply even to Owners until removed; they are inherited by child resources.
- Azure portal = web-based GUI. Cloud Shell = browser-based shell (Bash or PowerShell) with tools pre-installed, authenticated. Azure CLI = cross-platform command line (az commands). Azure PowerShell = cmdlets (e.g. New-AzVM). Azure Arc = extend Azure management (policy, RBAC, monitoring) to servers, Kubernetes and data services on-prem or in other clouds. Infrastructure as code = describe infrastructure in code files, repeatable deployments. Azure Resource Manager (ARM) = the deployment and management service; every request from portal/CLI/PowerShell/SDK goes through it. ARM templates = declarative JSON files; Bicep is a simpler language that compiles to ARM templates.
- Azure Advisor = personalised recommendations in five categories: reliability, security, performance, operational excellence, cost. Azure Service Health = Azure status (global view of all regions), Service Health (services and regions YOU use; planned maintenance, health advisories), Resource Health (health of YOUR individual resources). Azure Monitor = collect, analyse and act on telemetry; Log Analytics = write/run queries (KQL) on log data; Azure Monitor alerts = notify/act when a condition is met; Application Insights = monitor web application performance and usage (APM).
